# كيمو — حزمة تأمين انتقالية لـ Firebase

## ما الموجود؟
- `public/index.html`: نسخة HTML مبنية على الملف الأصلي، مع الحفاظ على الواجهة، وإزالة كلمات المرور التجريبية من بيانات الأنشطة، وإزالة تخزين حسابات الإدارة في `localStorage`، وتغيير تسجيل الدخول إلى Firebase Authentication مع التحقق من مستند `users/{uid}`.
- `firestore.rules`: قواعد انتقالية مغلقة للكتابة. تسمح للمستخدم بقراءة ملف دوره فقط، وللزوار بقراءة الأنشطة المعتمدة فقط إذا كانت موجودة في Firestore. جميع عمليات الكتابة إلى Firestore معطلة حاليًا.
- `firebase.json` و`.firebaserc`: إعداد أولي لـ Firebase Hosting للمشروع `kimo-yemen`.

## حدود مهمة — لا تعتبر هذه النسخة دمجًا سحابيًا كاملًا
واجهة كيمو الأصلية تحتوي وظائف كثيرة تعتمد على `localStorage`. هذه النسخة لم تنقل كل عمليات إضافة/تعديل/موافقة الأنشطة والإشعارات إلى Firestore، ولم تنقل الصور إلى Firebase Storage. لذلك أضيف تنبيه واضح في لوحة الإدارة، وأُوقف إرسال طلبات الأنشطة مؤقتًا حتى لا تُجمع كلمات مرور وتُخزّن محليًا. لا تستخدمها باعتبارها نسخة إنتاج مكتملة.

## إعداد حساب المالك
1. في Firebase Console > Authentication > Users، أنشئ مستخدمًا ببريد إلكتروني تملكه وكلمة مرور قوية.
2. انسخ UID للمستخدم.
3. في Firestore > Data، أنشئ مجموعة `users` ومستندًا معرّفه هو UID نفسه.
4. أضف الحقول: `role` (string) = `owner`، و`active` (boolean) = `true`، و`name` (string) اختياري.
5. لا تسمح للموقع العام بإنشاء أو تعديل مستندات `users`. هذه القواعد تمنع ذلك.

## حساب مشرف
أنشئ المستخدم من Authentication، ثم أنشئ مستند `users/{uid}` يدويًا من لوحة Firebase أو من خادم موثوق، مع `role: "admin"` و`active: true` و`permissions` (map) حسب الحاجة. لا تُنشئ دور المشرف من HTML.

## حساب صاحب نشاط
يتطلب حساب صاحب النشاط مستند `users/{uid}` يحتوي `role: "business"` و`active: true` و`businessId` (string)، مع مستند مطابق في `businesses/{businessId}` يحتوي `ownerUid` يساوي UID وحالة `status: "approved"` كي يسمح له مسار الدخول الحالي بفتح لوحة النشاط. لم يُبنَ بعد تدفق إنشاء/اعتماد هذه الحسابات؛ أنشئها يدويًا للاختبار فقط.

## قواعد Firestore
القواعد المرفقة متحفظة: لا تسمح بأي كتابة من المتصفح. انشرها فقط إذا كنت موافقًا على إيقاف عمليات الكتابة السحابية في الوقت الحالي. لا تستبدلها بقواعد `allow read, write: if true` مطلقًا.

## اختبار محلي
1. احتفظ بنسخة احتياطية من HTML الأصلي.
2. فك الحزمة إلى مجلد.
3. افتح Terminal داخل المجلد وشغّل `npm install -g firebase-tools` ثم `firebase login`.
4. تأكد من الحساب والمشروع عبر `firebase use kimo-yemen`.
5. لنشر القواعد فقط: `firebase deploy --only firestore:rules`.
6. لنشر صفحة الاستضافة: `firebase deploy --only hosting`.

هذه الأوامر لا تُنفّذ تلقائيًا من الحزمة؛ لا يتم أي نشر حتى تشغّلها بنفسك. اختبر الموقع على نطاق Firebase Hosting بعد إضافة النطاق إلى Authentication > Settings > Authorized domains.

## قبل الإنتاج
يجب استكمال مزامنة الأنشطة والطلبات والإشعارات مع Firestore، ورفع الصور إلى Storage، وإضافة قواعد كتابة دقيقة، ونقل إدارة الحسابات إلى خادم موثوق أو Firebase Admin SDK/Cloud Functions. كما ينبغي مراجعة أي بيانات قديمة لأن القواعد المفتوحة سابقًا كانت تسمح بالقراءة والكتابة العامة.
